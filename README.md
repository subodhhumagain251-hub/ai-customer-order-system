# 🤖 AI Customer Order Automation Backend API

A modular Python backend for automating customer order workflows for small retail and social-commerce businesses.

Built with **FastAPI**, **Pydantic**, and a decoupled business-logic architecture, this project provides a solid foundation for managing customer orders, validating data, tracking order lifecycles, and generating business metrics.

## 📌 The Problem

Small and medium-sized social-commerce businesses often spend hours manually:

- Tracking customer orders across messaging platforms
- Managing inventory using spreadsheets
- Monitoring order statuses
- Calculating sales and business metrics

This project provides a backend foundation to automate those workflows.

---

## ✨ Features

- **Full CRUD API** — Create, retrieve, update, and delete customer orders.
- **Strict Validation** — Uses Pydantic and defensive validation to prevent invalid prices, quantities, and missing data.
- **Order Lifecycle Management** — Track orders from `PENDING` to later stages such as `PAID`, `SHIPPED`, and `DELIVERED`.
- **Decoupled Architecture** — Business logic is separated from the HTTP/API layer for better maintainability and reusability.
- **JSON Persistence** — Orders are safely stored and restored from a local JSON file.
- **Business Metrics** — Calculate total revenue and items sold.
- **RESTful Standards** — Uses appropriate HTTP status codes such as `200`, `201`, `404`, and `422`.
- **Interactive API Docs** — Swagger UI is automatically generated by FastAPI.

### Architecture

The project separates responsibilities into two main layers:

```text
Client Request
      │
      ▼
┌───────────────┐
│   FastAPI     │  ← HTTP routes & validation
│    api.py     │
└───────┬───────┘
        │
        ▼
┌───────────────┐
│ Business Logic│  ← Order management & CRUD
│orders_manager │
└───────┬───────┘
        │
        ▼
┌───────────────┐
│  orders.json  │  ← Local persistence
└───────────────┘
```

This separation makes the core logic reusable for future APIs, CLI tools, workflow automation, or AI integrations.

## 🔌 API Endpoints

| Method | Endpoint | Description | Status |
|--------|----------|-------------|--------|
| `GET` | `/` | Health check and welcome route | `200 OK` |
| `GET` | `/orders` | Retrieve all customer orders | `200 OK` |
| `GET` | `/orders/{order_id}` | Retrieve a specific order | `200 OK` / `404 Not Found` |
| `POST` | `/orders` | Create a new customer order | `201 Created` / `422 Error` |
| `PATCH` | `/orders/{order_id}/status` | Update an order's status | `200 OK` / `404 Not Found` |
| `DELETE` | `/orders/{order_id}` | Delete an order record | `200 OK` / `404 Not Found` |
| `GET` | `/metrics` | Calculate revenue and items sold | `200 OK` |

## 🚀 Getting Started

### 1. Clone the Repository

```bash
git clone https://github.com/subodhhumagain251-hub/ai-customer-order-system.git
cd ai-customer-order-system
```

### 2. Create a Virtual Environment

```bash
python -m venv .venv
```

**Windows:**

```bash
.venv\Scripts\activate
```

**macOS/Linux:**

```bash
source .venv/bin/activate
```

### 3. Install Dependencies

```bash
pip install fastapi uvicorn pydantic
```

### 4. Start the API

```bash
uvicorn api:app --reload
```

The API will be available at:

```text
http://127.0.0.1:8000
```

## 📚 Interactive API Documentation

FastAPI automatically generates interactive API documentation.

Once the server is running, open:

```text
http://127.0.0.1:8000/docs
```

From Swagger UI, you can test every available endpoint directly from your browser.

### Example: Create an Order

**POST** `/orders`

```json
{
  "customer": "Ayush",
  "product": "Winter Jacket",
  "quantity": 1,
  "price": 4000
}
```

The system validates the request, generates an order ID, and assigns the default order status.
